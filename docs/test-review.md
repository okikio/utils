# Test review

Each canonical test file has an owner and a concrete reason to remain. The review distinguishes tests of the same
focused API from a composed consumer flow. Repeated setup is useful when it isolates ownership; repeated assertions for
the same flow belong in one authoritative suite.

The machine-readable inventory is [qualification.json](qualification.json). Its checker discovers tests and publishable
manifests from the working tree, so a new package or test requires an explicit qualification decision. This readable
table is a review companion, not a snapshot assertion against headings, prose, test names, or assertion counts.

## Fixtures and helpers

The CSV [fixture manifest](../packages/csv/fixtures/manifest.json) records byte encoding, delimiter/header discovery,
and expected normalized output separately from parser execution. Stress and edge-case files test incremental input and
malformed boundaries. The independent encoder in `packages/csv/properties.test.ts` supplies original expected cells; it
does not call the production writer to decide whether the production parser is right.

Worker/process fixture modules define explicit schema-checked jobs and framed host entrypoints. Their gates and effect
acknowledgements synchronize real native execution. Paired in-memory transport doubles qualify protocol behavior
separately from native host integration. The restart scenario uses in-memory history and an idempotent sink; it
demonstrates replacement of an execution replica and never claims disk-backed crash recovery.

Promise resolvers, `TestClock`, resource doubles, independent route matchers, and captured reporters make the observed
contract controllable. Cleanup is owned by `await using`, `finally`, or an immediately registered test cleanup hook. The
bounded native descendant polling and stuck-test watchdog are separately reviewed exceptions in
[fragile-exceptions.json](fragile-exceptions.json). They diagnose host progress and impose no speed threshold.

The final source gate exposed a tooling defect in colored Deno documentation diagnostics. `tools/check-docs.test.ts`
adds independent plain/ANSI and unknown-code/location-free fault controls. The gate now normalizes terminal controls
before reading stable codes and source locations; it does not assert explanation text.
